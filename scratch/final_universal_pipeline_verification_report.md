## 1. Що було перевірено

1. **Єдиний перелік робочих таймфреймів**:
   - Перевірено централізацію в `backend/app/research/pipeline.py` виключно 6 робочих інтервалів:
     ```python
     TIMEFRAMES = ["1m", "5m", "15m", "1h", "4h", "1d"]
     ```
   - Перевірено відповідність кожного інтервалу його тривалості в секундах (`1m: 60s`, `5m: 300s`, `15m: 900s`, `1h: 3600s`, `4h: 14400s`, `1d: 86400s`).
   - Перевірено коректність ієрархії старших таймфреймів (HTF-мапінг):
     `1m -> 5m`, `5m -> 15m`, `15m -> 1h`, `1h -> 4h`, `4h -> 1d`, `1d -> 1d`.
   - Перевірено суворе блокування та відхилення неавторизованих або застарілих інтервалів (`3m`, `30m`, `2h`, `8h`, `12h`, `1w`) через генерацію винятку `ValueError`.

2. **Динамічний ринковий всесвіт активів**:
   - Опитано живий біржовий контекст Hyperliquid (`hl_client.get_meta_and_contexts()`).
   - Виявлено **179 активних безстрокових контрактів** без жодного захардкодженного списку монет.
   - Перевірено сегментацію ринку на три ліквідні рівні (Tier 1: High Liquidity $\ge \$50\text{M}$, Tier 2: Mid Liquidity $\$5\text{M} - \$50\text{M}$, Tier 3: Emerging Liquidity $<\$5\text{M}$).
   - Підтверджено автоматичне виключення делістингованих монет та інструментів із нульовою ціною.

3. **Якість історичних даних та Point-in-Time безпека**:
   - Завантажено та протестовано реальні дані для всіх 6 таймфреймів на вибірці активів з різних рівнів ліквідності (`BTC`, `ETH`, `PUMP`, `CASHCAT`).
   - Перевірено хронологічне сортування, відсутність дублікатів міток часу та відсутність розривів (> 1.5 кроку).
   - Підтверджено відсікання незакритих свічок поточного періоду: час закриття останньої свічки завжди $\le$ поточному часу евалюації, що гарантує повну відсутність Look-Ahead Bias.
   - Перевірено адаптивну глибину історії: 1m отримує до 3000 свічок, тоді як 1d використовує реалістичну глибину 1000 свічок.

4. **Ізоляція файлового кешу**:
   - Перевірено збереження кожного датасету в окремий файл за шаблоном `{COIN}_{TF}.json`.
   - Підтверджено відсутність перехресного забруднення між активами та між різними таймфреймами однієї монети.

5. **Регресійний аудит проєкту**:
   - Виконано спеціалізовані тести універсального pipeline (`test_universal_research_pipeline.py`).
   - Виконано повний бекенд-сьют (149 тестів).
   - Виконано фронтенд-сьют (41 тест) та перевірено продакшн-білд (`tsc && vite build`).

## 7. Виявлені обмеження (Transparent Limitations)

   - Молоді інструменти (наприклад, `CASHCAT` або `PUMP`) мають фактичну історію на біржі меншу, ніж максимальний запитуваний ліміт 1d-свічок (наприклад, 120 днів для `CASHCAT`). Це є об'єктивною біржовою властивістю активу, конвеєр коректно повертає всю наявну історію зі статусом `VALID`.
2. **Ліміт snapshot API Hyperliquid**:
   - Одноразовий біржовий запит повертає до 5000 свічок. Для робочих завдань Hyperscreener (глибина від 1000 до 3000 свічок) цього достатньо без додаткової багатосторінкової пагінації.
